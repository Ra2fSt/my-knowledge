## 核心问题

如何在忽略机器常数的条件下比较算法随输入规模增长的代价？先明确 n 是元素数、顶点数还是位数。

## 考点清单

- [ ] 逻辑结构、存储结构、抽象数据类型与算法性质。
- [ ] O、Ω、Θ 的含义；最好、最坏、平均情况分别描述什么。
- [ ] 顺序、嵌套、倍增/折半循环的执行次数；不能机械地数循环层数。
- [ ] 递归调用树与递归深度；辅助空间包括调用栈。

## 必会比较

| 形态                    | 典型增长阶      | 注意               |
| ----------------------- | --------------- | ------------------ |
| 从 1 不断乘 2 直到 n    | Θ(log n)        | 底数只影响常数     |
| 第 i 轮执行 i 次，i=1…n | Θ(n²)           | 先求和再取主导项   |
| 平衡二分，每次只走一支  | Θ(log n) 次递归 | 每层工作必须另计   |
| 一次扫描所有元素        | Θ(n)            | 输入读取本身有成本 |

## 易混与联系

O 是渐进上界，不能把所有上界都叫紧确复杂度；平均复杂度依赖输入分布，均摊复杂度分析的是一串操作的总成本。[[co-system|系统与性能]] 的运行时间还包含指令与硬件成本。
