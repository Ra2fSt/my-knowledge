## 文件位置与组织方式

- Markdown 唯一内容源：`src/content/notes/*.md`。**暂时保持扁平目录**，用 parent 组成逻辑树；现有双链插件按顶层文件建立索引，不要擅自挪进子文件夹。
- 大章节：`section: computer-foundations`。
- 层次：`kind: hub | subject | chapter | concept`。
- 父节点：`parent` 为已存在的文件 id（不含 `.md`），形成无环目录。
- 顺序：`order` 为非负整数；同父节点的上一篇/下一篇按此顺序。
- 内容完整度：`coverage: outline | overview | detail`，对应骨架待填 / 总览已建 / 详细笔记。
- 个人掌握状态：`status: learning | organizing | mastered | archived`，与 coverage 独立。
- 固定科目名与颜色在 `src/lib/subjects.ts`；不要把「计组」「计算机组成原理」当成两个分类。
- 页面日期和状态来自 Markdown；新内容完成后更新 updatedDate。
- Markdown 任务清单是编辑时维护的静态清单，不是浏览器内保存的打卡系统。

## 关系与线宽

普通正文双链自动产生 1 级细线；parent 自动产生 3 级章节线。要标明更重要的联系，使用 relations：

| type         | 从当前笔记指向 target 的语义   |
| ------------ | ------------------------------ |
| prerequisite | 当前内容依赖 target 的先修知识 |
| support      | 当前内容与 target 相互支撑     |
| application  | 当前知识应用到 target          |
| contrast     | 当前内容与 target 作对照辨析   |

strength 只能是 1、2、3：弱关联、支撑联系、核心联系。**它不是考试频率、学习进度或自动统计值**。reason 必须说明为什么有这条关系。

同一对节点的双向引用合并成一条线，线宽取最大强度，全部方向说明保留在悬停和文字视图中。图谱本身不使用箭头，避免把双向关系错误表达成单向依赖。关系也进入出链、反链、相关推荐；笔记页展示进出关系说明。不存在的 parent/relations 目标、自指与父级循环会使构建失败。

图谱支持范围、单科、最小强度筛选。单科筛选只保留该科节点和科内边；看跨科关系请选择全部学科。默认只显示主节点/悬停邻居标题，勾选可显示全部。全局上限 200 节点，局部上限 60 节点，超出全局上限会提示。
